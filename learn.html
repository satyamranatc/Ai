Chapter 01

Machine Learning Algorithms

Machine learning enables systems to learn patterns from data without being explicitly programmed. Every modern AI system is built on its foundations.

What is Machine Learning?

Machine learning is the discipline of designing algorithms that improve through experience. Rather than programming explicit rules, ML systems are trained on datasets and extract statistical patterns to make decisions on unseen data.

The fundamental ML loop is: Data → Features → Model → Predictions → Evaluation → Refinement. Every algorithm variant operates within this cycle.

Supervised Learning

Models learn from labeled training examples, mapping inputs to known outputs. The goal is to generalize this mapping to new, unseen inputs.

Linear Regression Predicts continuous values by fitting a hyperplane. Closed-form solution via OLS.
Logistic Regression Binary classification using sigmoid activation. Outputs probabilistic class membership.
Decision Trees & Random Forest Hierarchical feature splitting. RF ensembles reduce variance via bagging.
Gradient Boosting (XGBoost, LightGBM) Sequential weak learners correcting prior errors. State-of-the-art on tabular data.
Support Vector Machines (SVM) Maximizes margin hyperplane using kernel trick for non-linear boundaries.
Key Metrics: Accuracy · Precision · Recall · F1 · AUC-ROC · RMSE
🔍

Unsupervised Learning

Discovers hidden structure and latent patterns in unlabeled data, without predefined correct answers.

K-Means Clustering Partitions data into K clusters by minimizing intra-cluster variance via EM iteration.
DBSCAN Density-based clustering, robust to arbitrary shapes and noise detection.
PCA (Principal Component Analysis) Orthogonal projection reducing dimensionality while preserving maximum variance.
t-SNE / UMAP Non-linear embeddings for high-dimensional data visualization and manifold discovery.
Hierarchical Clustering Agglomerative bottom-up merging or divisive splitting creating dendrogram structures.
Key Metrics: Silhouette Score · Calinski-Harabasz · Davies-Bouldin
🎮

Reinforcement Learning

An agent learns to take actions in an environment to maximize cumulative reward signal, through trial, error, and delayed feedback.

Q-Learning & DQN Learns action-value Q-function. DQN uses neural nets for high-dimensional state spaces.
Policy Gradient (REINFORCE) Directly optimizes the policy π(a|s) using Monte-Carlo returns.
PPO (Proximal Policy Optimization) Clips policy updates for stable training. State-of-art for continuous control & LLM alignment.
AlphaGo / AlphaZero MCTS + RL for superhuman game play. Self-play without human data.
Model-Based RL (Dreamer, MuZero) Learns a world model for planning ahead. Superior sample efficiency.
Key Concepts: State · Action · Reward · Policy π · Value V(s) · Q(s,a)
Core Mathematics

The Loss Minimization Framework

Gradient Descent Update Rule
θt+1 = θt − η · ∇θL(θt)
Iteratively update parameters θ in direction of steepest loss descent, scaled by learning rate η.
MSE Loss (Regression)
L = (1/n) Σ (ŷᵢ − yᵢ)²
Average squared difference between predictions and true labels. Penalizes large deviations heavily.
Cross-Entropy Loss (Classification)
L = −Σ yᵢ · log(ŷᵢ)
Measures divergence between predicted probability distribution and ground truth one-hot labels.
Bias–Variance Tradeoff
Error = Bias² + Variance + Noise
Underfitting → high bias. Overfitting → high variance. The tradeoff determines model complexity.

Model Selection Guide

📋 Tabular data

Start with logistic/linear regression, then LightGBM or XGBoost. Usually beats deep learning here.

🏷️ Few labels

Use transfer learning, semi-supervised or clustering, and consider active learning.

🔍 Need explanations

Linear models, shallow trees, SHAP values for any model.

⚡ Real-time latency

Linear models or small tree ensembles; distil big models.

The ML Project Workflow

  1. Define the problem — target, metric, baseline and what a wrong prediction costs.
  2. Collect & split data — train / validation / test. Use time-based splits for temporal data.
  3. Explore & clean — missing values, outliers, duplicates, class balance.
  4. Feature engineering — encode categoricals, scale numerics, build domain features.
  5. Train a baseline — dummy model, then a simple model, then complex ones.
  6. Cross-validate & tune — k-fold CV with random or Bayesian search (Optuna).
  7. Evaluate on test once — report the right metric with confidence intervals.
  8. Deploy & monitor — watch for data drift and retrain on schedule.

Best Practices

🚰 Prevent Data Leakage
  • Fit scalers/encoders on train only.
  • Use sklearn Pipeline.
  • Never use future info to predict the past.
⚖️ Imbalanced Data
  • Stratified splits.
  • Class weights or resampling (SMOTE).
  • Tune the decision threshold.
🧮 Overfitting
  • Cross-validation, regularisation (L1/L2).
  • Limit tree depth, early stopping.
  • More data beats fancier models.
🔁 Reproducibility
  • Fix random seeds; version data and code.
  • Track experiments with MLflow.
🚫 Pitfalls
  • Tuning on the test set.
  • Reporting accuracy on imbalanced data.
  • Skipping the baseline.

Leak-Free scikit-learn Pipeline

pipeline.pypython · scikit-learn
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, cross_val_score, GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

pipe = Pipeline([
    ("scale", StandardScaler()),
    ("clf", RandomForestClassifier(random_state=42)),
])

print("CV F1:", cross_val_score(pipe, X_tr, y_tr, cv=5, scoring="f1").mean())

search = GridSearchCV(pipe, {"clf__n_estimators": [100, 300], "clf__max_depth": [None, 8]}, cv=5, scoring="f1")
search.fit(X_tr, y_tr)
print(search.best_params_)
print(classification_report(y_te, search.predict(X_te)))   # touch test set once

Deep Learning & Neural Networks

Deep learning stacks layers of non-linear transformations to learn hierarchical representations directly from raw data — powering vision, speech, and language AI.

How a Neuron Works

A single artificial neuron computes a weighted sum of its inputs, adds a bias term, and passes the result through a non-linear activation function to produce an output signal.

Stacking millions of such neurons in deep hierarchies allows networks to learn arbitrary complex functions — from recognizing faces to generating human-quality text.

Key Neural Network Architectures

Convolutional Neural Network (CNN)

Learns spatial feature hierarchies from grid-structured data. Convolutional layers detect local patterns (edges, textures, shapes). Used in image classification, object detection, and medical imaging.

Conv2D → BatchNorm → ReLU → MaxPool → Dense
📸 Computer Vision · MRI Diagnosis · Autonomous Vehicles

Recurrent Neural Network (RNN / LSTM)

Maintains hidden state across sequential timesteps. LSTMs solve vanishing gradient through gated memory cells. Ideal for time-series, speech, and natural language processing.

Embed → LSTM → Dropout → LSTM → Softmax
🎤 Speech Recognition · Stock Prediction · Machine Translation

Transformer Architecture ⚡

Attention is All You Need (2017). Parallel self-attention across entire sequences. Positional encoding replaces recurrence. Scaled to billions of parameters — the engine of all modern AI.

Embed → Multi-Head Attn → LayerNorm → FFN → Softmax
🚀 GPT-4 · BERT · Gemini · Claude · Whisper · DALL·E

Graph Neural Network (GNN)

Operates on graph-structured data, aggregating neighbor embeddings to learn node, edge, and graph-level representations. Used in drug discovery and social networks.

Node Embed → Message Pass → Aggregate → Update → Readout
💊 Drug Discovery · Fraud Detection · Recommendation Engines

Autoencoder & VAE

Encoder compresses data to a latent space; decoder reconstructs it. Variational autoencoders impose a probabilistic prior over the latent space, enabling generative sampling.

Input → Encoder → Latent z → Decoder → Output
🖼️ Image Compression · Anomaly Detection · Data Augmentation

Diffusion Networks (U-Net)

Iteratively denoise random Gaussian noise toward a learned data distribution. U-Net skip connections preserve spatial detail. The backbone of Stable Diffusion and DALL·E 3.

Noise x_T → U-Net Denoise → x_T-1 → ... → x_0
🎨 DALL·E 3 · Stable Diffusion · Sora · Imagen Video
Neural Network Mathematics

Backpropagation & Chain Rule

Forward Pass
zl = Wlal-1 + bl
al = σ(zl)
Inputs flow forward through weight matrices W and bias b, with activation function σ applied at each layer l.
Backward Pass (Chain Rule)
δl = (Wl+1)ᵀδl+1 ⊙ σ′(zl)
Error signal δ propagates backward, scaled by transposed weights and element-wise activation derivatives.
Weight Gradient
∂L/∂Wl = δl(al-1)ᵀ
Gradient of loss with respect to weight matrix W at layer l — used directly for parameter updates.
Attention Score
Attn(Q,K,V) = softmax(QKᵀ/√dₖ)V
Transformer self-attention: scaled dot product between queries Q and keys K, weighting values V.

Training Neural Networks the Right Way

Deep learning works when data, architecture and optimisation are all sound. These are the habits that separate stable training from mysterious divergence.

Choosing Components

ComponentDefault ChoiceWhy / Alternatives
ActivationReLU / GELUAvoids vanishing gradients. Use GELU/SiLU in transformers, Sigmoid/Softmax only at outputs.
OptimizerAdamWRobust default. SGD+momentum can generalise better for CNNs.
Learning rate1e-3 (Adam), 1e-5 (fine-tune)Most important hyper-parameter. Use warmup + cosine decay or OneCycle.
InitialisationHe / XavierKeeps activation variance stable across layers.
NormalisationBatchNorm (CNN), LayerNorm (transformer)Faster, more stable training.
LossCrossEntropy / MSEMatch the task. Use label smoothing and focal loss for imbalance.
RegularisationDropout, weight decay, augmentationFight overfitting; early stopping is free.

Best-Practice Checklist

🧪 Debug First
  • Overfit a single small batch — loss should go to ~0.
  • Check initial loss ≈ ln(num_classes).
  • Visualise inputs and labels.
📈 Optimisation
  • Gradient clipping (norm 1.0) for RNNs/transformers.
  • Mixed precision (bf16/fp16) for ~2× speed.
  • Gradient accumulation for big effective batches.
🗂️ Data
  • Normalise inputs; augment images/audio.
  • Split train/val/test before any processing.
  • Watch for label noise and leakage.
🔁 Transfer Learning
  • Start from pretrained weights (ResNet, ViT, BERT).
  • Freeze backbone, train head, then unfreeze with low LR.
  • Use LoRA to fine-tune large models cheaply.
📊 Monitoring
  • Track train/val loss, metrics and LR every epoch.
  • Use TensorBoard or Weights & Biases.
  • Save checkpoints and seeds for reproducibility.
🚫 Common Failures
  • Loss = NaN → LR too high or bad data.
  • Train ↓ val ↑ → overfitting.
  • Both stuck high → underfit, LR too low.
  • Forgetting model.eval() at inference.

Reference PyTorch Training Loop

train.pypython · pytorch
import torch, torch.nn as nn
from torch.utils.data import DataLoader

device = "cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu"

model = nn.Sequential(nn.Linear(20, 64), nn.ReLU(), nn.Dropout(0.2), nn.Linear(64, 2)).to(device)
opt   = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=20)
loss_fn = nn.CrossEntropyLoss()

best = float("inf")
for epoch in range(20):
    model.train()
    for x, y in train_loader:                 # DataLoader(train_ds, batch_size=64, shuffle=True)
        x, y = x.to(device), y.to(device)
        opt.zero_grad()
        loss = loss_fn(model(x), y)
        loss.backward()
        nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()
    sched.step()

    model.eval()
    with torch.no_grad():
        val = sum(loss_fn(model(x.to(device)), y.to(device)).item() for x, y in val_loader) / len(val_loader)
    if val < best:                            # early-stopping style checkpointing
        best = val
        torch.save(model.state_dict(), "best.pt")
    print(f"epoch {epoch} val_loss {val:.4f}")

How LLMs Learn & Generate

LLMs are trained via next-token prediction (causal language modeling). Given a sequence of tokens, the model learns to predict the most probable next token — billions of times, across hundreds of billions of documents.

At inference, the model autoregressively samples one token at a time. Temperature and top-p sampling parameters control diversity vs. accuracy of the output.

Core LLM Techniques & Capabilities

🔗

Retrieval-Augmented Generation (RAG)

Combines LLM generation with real-time retrieval from external knowledge bases. Solves the knowledge cutoff, prevents hallucinations, and allows private enterprise document access with strict citations.

Query → Query Rewrite → Hybrid Search → Top-50 Chunks → Cross-Encoder Rerank → Top-5 Chunks → LLM Synthesis
Open Dedicated RAG Architecture Guide →
🧩

Few-Shot & Chain-of-Thought Prompting

In-context learning allows LLMs to adapt behavior through examples in the prompt without weight updates. Chain-of-Thought (CoT) prompting instructs the model to reason step-by-step, dramatically improving math and logic performance.

System Prompt → Few-Shot Examples → "Think step by step" → Multi-step Reasoning → Final Answer
⚡

Mixture of Experts (MoE)

Sparse model architecture where only a subset of "expert" sub-networks are activated per token. Allows scaling to trillions of parameters with the compute cost of a much smaller dense model. Used in GPT-4 and Mixtral.

Token → Router → Top-2 Expert FFNs → Weighted Combination → Next Layer
🔧

Parameter-Efficient Fine-Tuning (LoRA)

LoRA decomposes weight updates into low-rank matrices: ΔW = BA. Only 0.1–1% of original parameters are trained, with minimal quality loss. Enables fine-tuning 70B models on consumer hardware in hours.

Frozen W + LoRA ΔW(BA) → Domain-Adapted Model → Merge or PEFT Serving

How LLMs Work Under the Hood

Behind the conversational magic of ChatGPT and Claude is an autoregressive transformer decoder performing billions of matrix multiplications. Here is the exact mathematical and engineering lifecycle of every prompt:

🔤

1. Tokenization & Positional Encodings

Text is chopped into sub-word tokens via Byte-Pair Encoding (BPE). Each token maps to a unique integer ID (e.g. "transformer" → ID 42189). Because transformers process all tokens simultaneously, sinusoidal or rotary positional embeddings (RoPE) are added so the network knows token order.

⚡

2. Multi-Head Self-Attention (Q, K, V)

Each token projects into Query (Q), Key (K), and Value (V) matrices. The dot-product score determines how much attention token A pays to token B: Attention(Q,K,V) = softmax(Q·Kᵀ / √d_k) · V

🎛️

3. Inference Sampling Dynamics

The final layer outputs logits over a 100k+ token vocabulary. Temperature scales logit entropy (0.0 = deterministic argmax; 1.0 = creative spread). Top-p (Nucleus) restricts sampling to the smallest pool of tokens whose cumulative probability exceeds p (e.g. 95%).

💾

4. KV-Caching Acceleration

During autoregressive text generation, recomputing attention over all prior tokens for every new word would be O(N²). The KV-Cache stores previous Key and Value vectors in GPU HBM memory, slashing token generation latency by 80%.

GPT · LLM Landscape

GPT & the Model Families

GPT (Generative Pre-trained Transformer) is a decoder-only transformer trained to predict the next token. Scale + instruction tuning + RLHF turned it into ChatGPT. Today several vendors and open-weight families compete.

  1. Pre-training — next-token prediction over trillions of tokens of web, books and code. Produces a base model that completes text but does not follow instructions.
  2. Supervised Fine-Tuning (SFT) — train on curated (instruction, ideal answer) pairs so the model learns the assistant format.
  3. Preference tuning (RLHF / DPO) — humans rank answers; a reward model or direct preference loss aligns outputs to be helpful, honest and harmless.
  4. Inference-time techniques — system prompts, tool calling, RAG, structured output and reasoning ("thinking") modes extend what the frozen weights can do.

Key Concepts You Must Know

🪙 Tokens & Context Window

Models read tokens (~¾ of a word). The context window is the max tokens of prompt + output. You pay per token, so shorter prompts are cheaper and faster.

🌡️ Temperature / Top-p

Low temperature (0–0.3) for extraction, code and facts. Higher (0.7–1.0) for brainstorming and creative text.

🛠️ Function Calling

The model returns a JSON request to call your function; your code executes it and sends the result back. This is the basis of agents.

⚠️ Hallucination

LLMs generate plausible text, not verified facts. Mitigate with RAG, citations, low temperature and output validation.

🎯 Fine-tune vs RAG vs Prompt

Start with prompting, add RAG for fresh/private knowledge, fine-tune only for style, format or domain behaviour.

🧠 Reasoning Models

Models like o-series and extended-thinking modes spend extra tokens on hidden chain-of-thought for math, logic and planning.

4 · Structured output & function calling

tools.pypython
import json
from openai import OpenAI
client = OpenAI()

def get_weather(city: str) -> str:
    return json.dumps({"city": city, "temp_c": 24})

tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Current weather for a city",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]

messages = [{"role": "user", "content": "Weather in Delhi?"}]
first = client.chat.completions.create(model="gpt-4o-mini", messages=messages, tools=tools)
call = first.choices[0].message.tool_calls[0]

messages.append(first.choices[0].message)
messages.append({"role": "tool", "tool_call_id": call.id,
                 "content": get_weather(**json.loads(call.function.arguments))})

final = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
print(final.choices[0].message.content)

6 · Embeddings (for search & RAG)

embed.pypython
import numpy as np
from openai import OpenAI
client = OpenAI()

docs = ["Cats purr.", "Stocks fell today.", "Dogs bark."]
vecs = np.array([d.embedding for d in client.embeddings.create(
    model="text-embedding-3-small", input=docs).data])
q = np.array(client.embeddings.create(
    model="text-embedding-3-small", input=["pet sounds"]).data[0].embedding)

scores = vecs @ q / (np.linalg.norm(vecs, axis=1) * np.linalg.norm(q))
print(docs[int(scores.argmax())])

GenAI Best Practices

✍️ Prompting
  • Give a role, task, format and examples (few-shot).
  • Ask for JSON and validate with Pydantic.
  • Put instructions first, data in delimiters.
  • Iterate with an eval set, not vibes.
🔐 Security
  • Keys in env vars / secret manager.
  • Treat retrieved text and user input as untrusted (prompt injection).
  • Never let the model run unsandboxed code or SQL.
💰 Cost & Latency
  • Use small models for easy tasks, route hard ones up.
  • Cache repeated prompts; trim context.
  • Stream responses; set max_tokens.
🧪 Reliability
  • Retry with exponential backoff on 429/5xx.
  • Set timeouts; log prompts, tokens, latency.
  • Evaluate with LLM-as-judge plus human spot-checks.
🚫 Avoid
  • Trusting outputs without verification.
  • Sending PII to third-party APIs unmasked.
  • Fine-tuning before trying prompt + RAG.

Framework · LangChain

LangChain in Simple Terms

LangChain is a Python library that connects LLMs to prompts, tools, data and memory. Instead of hand-writing API calls, you compose small reusable pieces into a pipeline.

Core Building Blocks

🤖 Chat Models

A uniform wrapper over OpenAI, Anthropic, Gemini, Ollama and more. Swap providers by changing one line.

📝 Prompt Templates

Reusable prompts with {variables} filled in at run time.

🧾 Output Parsers

Turn model text into strings, JSON or typed Pydantic objects.

🔗 Runnables & LCEL

Chain steps with the | pipe: prompt | model | parser. Supports invoke, stream and batch.

📚 Retrievers & Vector Stores

Load documents, split, embed and search them for RAG.

🛠️ Tools & Agents

Python functions the model can call. LangGraph runs the loop for you.

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "You explain topics simply."),
    ("user", "Explain {topic} in 2 sentences."),
])

chain = prompt | llm | StrOutputParser()      # LCEL pipe

print(chain.invoke({"topic": "gradient descent"}))

for chunk in chain.stream({"topic": "embeddings"}):   # streaming
    print(chunk, end="", flush=True)

4 · Simple RAG

rag.pypython · langchain
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

texts = ["LangChain composes LLM apps.", "FAISS is a vector search library."]
retriever = FAISS.from_texts(texts, OpenAIEmbeddings()).as_retriever(search_kwargs={"k": 2})

prompt = ChatPromptTemplate.from_template(
    "Answer using only this context:\n{context}\n\nQuestion: {question}")

rag = ({"context": retriever, "question": RunnablePassthrough()}
       | prompt | ChatOpenAI(model="gpt-4o-mini") | StrOutputParser())

print(rag.invoke("What is FAISS?"))

5 · A tool-using agent

agent.pypython · langgraph
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two integers."""
    return a * b

agent = create_react_agent(ChatOpenAI(model="gpt-4o-mini"), [multiply])
result = agent.invoke({"messages": [("user", "What is 12 times 34?")]})
print(result["messages"][-1].content)

The ReAct Framework

ReAct (Reasoning + Acting) interleaves chain-of-thought Thought steps with grounded Action steps, using Observations from tool results to guide the next thought. This cycle continues until the agent produces a final answer.

Thought
I need to find current GPU pricing. Let me search the web.
Action
web_search("NVIDIA H100 GPU price 2026")
Observation
NVIDIA H100 SXM5 80GB: $30,000 — $35,000 USD per unit. OEM availability Q1 2026.
Thought
Good. Now I can calculate the cluster cost for 1024 GPUs.
Action
calculator(32500 * 1024)
Observation
Result: $33,280,000
Final Answer
A 1024× H100 GPU cluster costs approximately $33.28M at current market rates.

How AI Agents Work in Production

An AI Agent is an LLM enhanced with a continuous reasoning loop, long-term memory, and tool invocation capabilities. Rather than generating a single text reply, an agent operates autonomously in an environment to achieve a defined goal:

Step 1

Perception & Ingestion

The agent receives user directives, system status, and environment state. Relevant memories are recalled from a vector database (Pinecone).

Step 2

Planning & ReAct Loop

The LLM breaks the high-level objective into sub-tasks (Thought). It chooses which tool to invoke and formats structured JSON parameters (Action).

Step 3

Tool / Function Execution

The runtime host intercepts the tool call (SQL query, API call, code interpreter), executes it securely, and feeds the result back to the model (Observation).

Step 4

Reflection & Self-Correction

If a tool returns an error or empty result, the agent reflects, corrects its strategy, and retries with revised arguments until the goal is achieved.
